# Duas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bundled library of about 36 authentic duas, browsable from Mer, with links from Oversikt, the Ramadan card and the Laylat-ul-Qadr card.

**Architecture:** One pure data module (`src/lib/duas.ts`) holds categories, duas and two lookups. Two expo-router screens (`src/app/duas/index.tsx`, `src/app/duas/[id].tsx`) render it with the existing UI primitives. Three existing components get a link each. A node script checks the data and prints the IRN review document.

**Tech Stack:** Expo SDK 54, expo-router, React Native, TypeScript, existing `src/components/ui` primitives.

**Spec:** `docs/superpowers/specs/2026-09-25-duas-design.md`

## Global Constraints

- Work stays on branch `feat/duas`. Never push or merge to `main` until the user approves.
- UI text is Norwegian bokmål. Never nynorsk. Never the em dash.
- No code comments.
- Colors only through `useTheme()` roles.
- Prayer names spelled Jumuah and Dhuhr in anything a human reads.
- Only duas with a sahih or hasan narration; every dua has a `source`.
- No suhoor-intention dua. No audio, favourites, search, sharing or tasbih counter.
- No new tab.

## Review Focus

- Unknown dua id or unknown category in a route param: show `EmptyState`, never crash.
- Very large font scale: Arabic must wrap, not clip; transliteration and meaning stay readable.
- Dark mode: all new surfaces read from theme roles, nothing hardcoded.
- Arabic direction: right aligned with `writingDirection: 'rtl'` on both platforms.
- Link ids from Oversikt, RamadanCard and NightCard must exist in the data; the check script asserts it.

- [ ] **Step 1: Write the check script first** (`scripts/duas.mjs`).
